AEM Tech Stack

The four AEM building blocks used daily — how markup, authoring, page structure and asset delivery fit together.

01

Components

HTL / Sightly components

  • Server-side HTL markup with Sling Models / data-sly-use
  • data-sly-list, data-sly-test, data-sly-resource patterns
  • Proxy components inheriting Core Components
  • BEM-based SCSS scoped per component
02

Dialogs

Touch UI authoring dialogs

  • Granite / Coral UI dialogs built in cq:dialog
  • Fields: textfield, RTE, pathfield, image, multifield
  • Tabbed dialogs with show/hide field logic
  • Design dialogs (cq:design_dialog) for policy-level settings
03

Templates

Editable templates & policies

  • Editable templates with structure, initial & layout containers
  • Policies controlling allowed components per container
  • Page components extending a shared base page
  • Responsive grid & locked structure for brand consistency
04

Clientlibs

CSS / JS delivery

  • cq:ClientLibraryFolder with categories & dependencies
  • css.txt / js.txt ordering, embed for bundling
  • Site-wide vs component-level libs to cut payload
  • Minification, cache-busting and clientlib debugging
07

Frontend Engineering Approach

SCSS discipline meets
defensive JavaScript

SCSS / CSS Strategy

› Component-oriented styles, isolated & predictable
› Breakpoints based on design requirements
› Reusable spacing, typography & layout patterns
› Focused selectors to reduce specificity conflicts
› Validated active, disabled, expanded, loading, error states

JavaScript / jQuery Strategy

› Initialize behavior only for components present on page
› Event delegation to reduce unnecessary handlers
› Reusable utilities kept separate from component logic
› Handle dynamic states: menus, tabs, accordions, sliders, forms
› Defensive checks for optional DOM elements

Key lessons learned

› Reusable components reduce both build effort and long-term maintenance cost.

› AEM frontend work requires equal attention to UI quality and authoring behavior.

› Responsive behavior should be designed at component level, not bolted on last.

› Good clientlib structure prevents avoidable CSS/JS integration problems.

› Debugging is faster when UI, HTL, clientlibs and browser behavior are isolated.
